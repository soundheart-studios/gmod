gmod · the CI gate

A test only counts if it fails without the change.

Pull requestbranch gmod/<job>
1 · Is it allowed?
The job
  • in main's plan, read from main
  • what it waits for is on main
  • claimed, and committed by the claimant
  • only the job's files
  • main still protected as declared
2 · Is it proven?
The proof
  • the criteria pass with the change
  • code put back, new tests kept: the criteria must fail
3 · Is it right?
The review
  • each criterion met
  • the tests are real
  • it stays within the goal
  • it keeps every rule (ADR)
Landsonce both pass and it's up to date with main
Rules changing?
Plan, ADRs or CI

A change to the plan, the rules or CI must come alone, never mixed with code. The review then asks one question: does it weaken what is checked? If it does, it doesn't land.

Fails closed: no answer from the reviewer, or one it can't read, stops the merge. A maintainer can overrule a fail with the gmod-override label.
