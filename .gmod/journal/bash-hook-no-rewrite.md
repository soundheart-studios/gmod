- 2026-11-08T15:16:40.677Z dev@soundheart.io: Done: gated() and its git() shell function are gone. hooks/shell.ts gains commitDirs(cmd), a quote-aware reader that finds each `git commit` and the directory it runs in (following cd/pushd along the command, git -C, skipping -c/--git-dir/--work-tree/--namespace/--config-env values, env assignments and command/exec/time/nice), and resolveDir() to place it from the session's cwd (~ via $HOME). The Bash hook runs `gmod gate-commit --shell --dir <dir>` for each before next(); a refusal is a deny with the gate's text, a pass runs the command exactly as written. Mentions of commit (grep, log -S, echo 'git commit', commit messages, comments, $(…)) are not gated. Trade-off: the gate now runs before the command, not as git commit starts, so (1) commits inside scripts or make targets aren't gated (a git pre-commit hook could later), and (2) the no-claim "CI change on its own" path looks at the index before a `git add` in the same command has run, so `git add .github/x && git commit` with no claim is refused; CI changes go through planned jobs and mcp__gmod__commit now (ci-change-job), so this is rare. Worked in a separate worktree so other sessions kept loading main's hook.
